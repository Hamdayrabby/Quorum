Abstract

Quorum is a debate arena in which five large-language-model agents, each powered by a different provider, argue one proposition. Two agents build opposing opening cases; two audit and attack both sides; a judge delivers a scored, structured verdict. The system is a staged pipeline: agents inside a stage run concurrently, every state change streams to the interface, and any agent failure degrades gracefully instead of crashing the debate. The project demonstrates provider diversity, async engineering, and failure-first design in a single usable product.

01 Introduction

Modern LLM applications rarely rely on a single model. Different providers exhibit different reasoning styles, cost profiles, and failure modes. Quorum turns that diversity into a deliberation protocol: five agents with distinct roles collaborate and compete, and a neutral judge turns the exchange into an explicit, scored decision.

The product goal is a live arena: the user submits a topic, watches five agents think in real time, and receives a verdict with winner, scores, fallacies, and key disagreements — rendered as a premium dark dashboard.

02 Objectives

  • Build a five-provider pipeline behind one interface (Google Gemini, River AI · DeepSeek, Mistral AI, River AI · GLM, NVIDIA NIM).
  • Run agents concurrently within stages (asyncio) while keeping stages strictly ordered.
  • Treat failure as a first-class outcome: retries with backoff, FAILED cards, a debate that always renders.
  • Prove it offline with mock-based test suites covering happy paths, failures, and timing.

    09 Verification & Conclusion

  • Offline smoke suite — 6 scenarios over a fake client: happy path, single opening failure, both fail, judge tolerance, parse fallback, parallel timing (< 0.35 s).
  • Error-path tests — missing key, 429-then-success, retry exhaustion, 401 fast-fail, empty content. Settings tests — override precedence, model discovery.
  • UI visual QA — every card / verdict state rendered and screenshot-checked in a real browser.

    • Conclusion. Quorum shows that model diversity can be an architecture: five providers contribute different reasoning styles to one structured outcome, while concurrency keeps latency low and graceful failure keeps the product usable under real-world API conditions. Future work: token streaming into the cards, multi-round rebuttals, and PDF export of debates.
