01 Objective

Quorum is a debate arena where five LLM agents, each powered by a different provider, argue a proposition: two build opposing opening cases, two audit and attack both sides, and a judge delivers a scored, structured verdict.

  • Demonstrate a real multi-provider, multi-agent pipeline — five different LLM vendors in one workflow.
  • Show staged concurrency (agents inside a stage run in parallel) and graceful failure — no single agent can crash the debate.

    04 Engineering Highlights

    Async client
    One OpenAI-compatible httpx client; 90 s timeout; agents call their providers concurrently.
    Smart retries
    Exponential backoff ~1s → ~2s (+ jitter), only on rate limits (429) and server errors (5xx). Auth errors fail fast.
    Graceful failure
    An agent failure becomes a FAILED card, never a crash; the debate always returns a renderable state.
    Structured verdict
    Judge output parsed as JSON (winner, scores, fallacies); if unparsed, the raw reply is shown unmodified — never invented.
    Live pipeline view
    Stepper + five status cards re-render on every state change: WAITING → THINKING → COMPLETED / FAILED.
    Runtime settings
    Sidebar: per-agent key + base URL, live connection test, model picker; overrides saved per agent.

    06 Failure Ladder (worst case handled)

  • One opening fails → the other still runs; analysis proceeds on the surviving case.
  • Both openings fail → stages 3–4 are skipped; a clear error is surfaced instead of a fake verdict.
  • Judge fails or replies garbage → error panel; the four analyses remain available below it.
  • Unparseable verdict → raw judge text shown as-is; the UI never fabricates content.

    08 The Arena Interface

  • Dark premium theme with per-agent accent colors; glyphs animate per role while an agent thinks.
  • Typewriter reveal — each argument appears as it is being typed, once.
  • Expand modal to read any full argument; copy button on every card.
  • Verdict panel with animated score bars, key disagreements, detected fallacies.
  • Settings sidebar: per-agent key, connection test, model picker; keys never echoed.
  • Honors prefers-reduced-motion; fully usable without JavaScript.

    • 09 Verification

  • Smoke suite (offline) — 6 scenarios over a fake client: happy path, single failure, total failure, judge tolerance, parallelism timing.
  • Error-path tests — missing key, 429-then-success, retry exhaustion, 401 fast-fail, empty content.
  • Settings tests — override precedence, key resolution, model discovery parsing.
  • UI visual QA — every card/verdict state rendered and screenshot-checked in a real browser.

    • 10 Conclusion & Future Work

    Quorum shows that model diversity is an architecture: five providers contribute different reasoning styles to one structured outcome, while concurrency keeps latency low and graceful failure keeps the product usable under real-world API conditions.

  • Streaming tokens live into the arena cards.
  • Multi-round debate: agents rebut each other before the verdict.
  • Export a debate as PDF / shareable link; debate history and replay.
